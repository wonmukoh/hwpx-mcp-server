# 05. 검증

**이 프로젝트의 심장이다.**

지금 MCP 를 고치면서 배운 것 하나로 줄이면 이렇다.

> XML 검사를 통과해도 한글이 안 그린다.

그림도, 머리말도, 각주도, 쪽 테두리도, 글꼴도 전부 그랬다.
파일 안에는 멀쩡히 들어 있고 시험도 통과하는데 화면에는 없었다.

그래서 검증을 **세 겹**으로 둔다. 위로 갈수록 느리고 확실하다.

```
3겹  시각 검증    한글로 PDF → PNG → 픽셀·좌표로 잰다      느리다. 개체를 건드리면 필수
2겹  왕복 검증    한글로 열었다 저장 → 우리 것과 비교       중간. 한글이 인정하는가
1겹  규격 검증    파싱·기하·무결성                          빠르다. 매 저장마다
```

---

## 1겹 — 규격 검증 (빠름, 항상)

저장할 때마다 자동으로 돈다. 통과 못 하면 **저장을 막는다.**

| 검사 | 무엇을 보나 |
|---|---|
| 왕복 무손실 | 파싱 → 직렬화 했을 때 원본과 같은가. `owpml` 계층의 합격 기준 |
| 태그 균형 | 열고 닫음이 맞는가 |
| 참조 무결성 | `charPrIDRef` 가 가리키는 `charPr` 이 실제로 있는가 |
| `itemCnt` | 선언한 개수와 실제 개수가 같은가 (안 맞으면 한글이 목록을 잘라 읽는다) |
| manifest | `content.hpf` 와 zip 안 파일이 맞는가 |
| BinData 압축 | 전부 STORE 인가 (한글은 압축된 것을 안 읽는다) |
| 표 기하 | 셀 폭 = 덮는 열 폭의 합 |
| 컨트롤 자리 | `</hp:secPr>` 다음이 `colPr` 인가 |

**전부 실제로 물렸던 것들이다.** 짐작으로 넣은 검사가 아니다.

---

## 2겹 — 왕복 검증 (중간, 기능마다)

한글 2024 로 우리 파일을 **열었다가 다시 저장**시키고 비교한다.

- 한글이 요소를 **버리면** → 우리 XML 이 틀렸다
- 한글이 **고쳐 쓰면** → 그 정규형이 정답이다. 처음부터 그렇게 쓴다
- **그대로 두면** → 한글이 인정한 것이다

하이퍼링크가 이걸로 판가름 났다. PDF 에 링크 주석이 없어서 실패인 줄 알았는데,
**한글이 만든 링크도 PDF 에는 주석을 안 남겼다.** 검증 기준이 틀렸던 것이다.
왕복시켜 보니 한글이 우리 링크를 받아들여 `Path` 를 채우고 갈래 값을 자기 것으로
고쳐 놓았다. 그래서 그 정규형을 그대로 쓰기로 했다.

> **검증 기준이 틀릴 수도 있다.** '안 나온다' 가 '틀렸다' 는 아니다.

## 3겹 — 시각 검증 (느림, 개체를 건드리면 필수)

```
HWPX ─(한글 COM)→ PDF ─(pdfplumber)→ PNG ─→ 눈 / 자
```

**사람 눈보다 자를 먼저 쓴다.** pdfplumber 가 글자와 선의 좌표를 준다.

| 재는 것 | 어떻게 |
|---|---|
| 요소가 나왔나 | 글자·선 개수 |
| 자리가 맞나 | `x0`, `top` 좌표 |
| 색이 맞나 | `non_stroking_color` (링크가 파란지 이걸로 확인했다) |
| 줄 간격 | 같은 칸 안 줄 사이 거리 (한글 기본 = 글자 크기 × 1.6 을 이렇게 쟀다) |
| 행 높이 | 표 가로선 사이 거리 |
| 글자가 잘렸나 | 글자 아래쪽이 셀 경계를 넘는가 |

사람이 보는 건 **마지막**이다. 자로 재서 통과한 뒤에 한 번 본다.

### 왜 이렇게까지 하나

시각 검증이 없었으면 못 잡았을 버그 목록:

- 그림이 파일에 있는데 화면에 없다 (BinData 압축)
- 머리말이 파일에 있는데 화면에 없다 (`headerFooter` 라는 없는 요소)
- 머리말을 넣었더니 쪽 테두리가 사라진다 (`colPr` 자리)
- 표 글자가 아래로 잘린다 (한글이 높이를 재계산 안 한다)
- 각주가 안 나온다 (`autoNum` 누락)
- 글꼴이 안 바뀐다 (목록에 없어서 0번으로 떨어짐)

**전부 XML 검사를 통과했다.**

## 기준 파일 — 추측하지 않기

새 기능을 만들기 전에 **한글로 그 기능을 쓴 파일을 만든다.**
COM 자동화라 사람이 클릭할 필요 없다.

```powershell
$hwp = New-Object -ComObject HWPFrame.HwpObject
$hwp.XHwpDocuments.Add(0)
$hwp.HAction.Run("InsertFootnote")     # ← 이 기능
...
$hwp.SaveAs($Out, "HWPX", "")
```

`자료/기준파일/` 에 넣고 우리 XML 과 **바이트 단위로 비교**한다.

지금까지 만든 것: `ref-column`(다단) `ref-link`(하이퍼링크) `ref-note`(각주·미주)
`ref-pagenum`(쪽번호). 앞으로 기능마다 하나씩 는다.

**기준 파일이 없으면 그 기능은 시작하지 않는다.**

## 기능 감사 — 조용한 실패 잡기

도구를 하나씩 실제로 부르고, 저장한 파일에 **흔적이 남았는지** 본다.

| 판정 | 뜻 |
|---|---|
| 통과 | 도구가 성공을 알리고 파일에도 흔적이 남았다 |
| **무동작** | 도구는 성공이라는데 파일이 그대로다. **제일 나쁘다** |
| 다르게씀 | 파일은 바뀌었는데 기대한 모양이 아니다 |
| 미구현 | 못 한다고 분명히 말했다. 정직한 것이다 |
| 실패 | 오류가 났다 |

지금 MCP 는 처음 감사에서 **무동작 21건**이었다. 지금은 0건이다.
새 프로젝트는 **무동작이 하나라도 나오면 빌드를 깬다.**

### 검사식도 의심한다

각주 검사가 `<hp:footNotePr>`(설정 태그)에 걸려 **늘 통과**하고 있었다.
코드에서 열 번 고친 함정을 검사 스크립트에서 또 밟은 것이다.

> 검사를 새로 쓰면 **일부러 고장 내서** 그 검사가 실패하는지 본다.

## 언제 무엇을 도나

| 때 | 1겹 | 2겹 | 3겹 |
|---|---|---|---|
| 저장할 때마다 | ● | | |
| 코드를 고치면 | ● | | |
| 기능을 새로 만들면 | ● | ● | ● |
| 개체(그림·표·각주·머리말)를 건드리면 | ● | ● | ● |
| 내보내기 전 | ● | ● | ● |

3겹은 Windows + 한글이 있어야 한다. **없는 곳에서는 1·2겹만 돌고, 3겹은 건너뛴 것으로
표시한다.** 조용히 통과시키지 않는다.

## 회귀 기준선

- 시험이 몇 개 통과하는지 **숫자를 적어 둔다.** 줄면 회귀다.
- 원본에서도 실패하는 것이 있으면 그 목록을 적고 **기준선으로 삼는다.**
  (지금 MCP 는 4건이 그렇다. 새로 만들면 0 이어야 한다)
- 한 번에 한 가지만 바꾸고 돌린다. 두 가지를 같이 바꾸면 어느 쪽인지 모른다.
